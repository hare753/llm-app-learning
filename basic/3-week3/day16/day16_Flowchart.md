# 二、数据流图（同一份数据怎么被加工）

以第二组 `fields = ["name", "years", "education"]` 为例：

```text
【输入数据】
   text    = "王五，28岁，本科，5年Python开发经验..."
   fields  = ["name", "years", "education"]
                            │
                            ▼
   ┌─────────────────────────────────────────────┐
   │ build_extract_prompt(fields)                │
   │   输入：fields 列表                          │
   │   过程：查字典 + 拼字符串 + json.dumps      │
   │   输出：system_prompt（一大段中文文本）      │
   └─────────────────────────────────────────────┘
                            │
                            ▼
       system_prompt = """
       你是一个结构化信息抽取器。请从用户文本中抽取以下字段：
       - name: 姓名，字符串。未提及填 null。
       - years: 工作年限，整数。未提及填 null。
       - education: 学历，字符串。未提及填 null。
       要求：
       1. 只输出一个合法 json ...
       2. 必须包含以下字段 ...：['name', 'years', 'education']
       3. 未提及的字段填 null ...
       4. 输出必须是合法 json。
       json 示例结构：
       { "name": null, "years": null, "education": null }
       """
                            │
                            ▼
   ┌─────────────────────────────────────────────┐
   │ client.chat.completions.create(...)         │
   │   messages = [                              │
   │     {"role":"system","content":system_prompt}│
   │     {"role":"user",  "content":text}        │
   │   ]                                         │
   └─────────────────────────────────────────────┘
                            │
                            ▼
                 ★ 网络请求 → DeepSeek ★
                            │
                            ▼
   ┌─────────────────────────────────────────────┐
   │ resp 返回                                   │
   │   resp.choices[0].message.content           │
   │       = '{"name":"王五","years":5,"education":"本科"}'│
   └─────────────────────────────────────────────┘
                            │
                            ▼
   ┌─────────────────────────────────────────────┐
   │ clean_json(raw)                             │
   │   strip → 剥 ```json/``` → strip             │
   │   输出：干净的 JSON 字符串                    │
   └─────────────────────────────────────────────┘
                            │
                            ▼
   ┌─────────────────────────────────────────────┐
   │ json.loads(...)                             │
   │   输出：Python 字典                          │
   │   result = {                                │
   │     "name": "王五",                          │
   │     "years": 5,                             │
   │     "education": "本科"                      │
   │   }                                         │
   └─────────────────────────────────────────────┘
                            │
                            ▼
   ┌─────────────────────────────────────────────┐
   │ 字段检查                                    │
   │   missing = [f for f in fields if f not in result]│
   │           = []  （都抽到了）                 │
   │   extra   = [f for f in result if f not in fields]│
   │           = []  （没多抽）                   │
   │   字段完整 = not missing = True              │
   └─────────────────────────────────────────────┘
                            │
                            ▼
                【输出到终端】
```

# 五、三个「关键岔路口」标记

这三个地方决定了程序走哪条路：

```text
岔路口 ①：_require_env 里
   ├─ Key / URL 都有 → 继续
   └─ 缺 → raise RuntimeError → 立即终止 ❌

岔路口 ②：if __name__ == "__main__":
   ├─ 直接运行 → 执行测试代码（阶段 B）
   └─ 被 import → 跳过阶段 B，仅完成阶段 A

岔路口 ③：json.loads 处
   ├─ 解析成功 → 返回 dict，继续字段检查
   └─ 抛 JSONDecodeError → except 捕获 → 返回 None
                          → __main__ 里打印"字段完整：False" → continue
```

# 六、一句话总结

> **整份文件 = 两个阶段 + 两个循环 + 一次网络请求：**  
> 阶段 A（准备工作，只跑一次）→ 判断 main → 阶段 B（for 循环 2 遍，每遍：生成 prompt → 调 API → 解析 → 检查）。

**最值得记住的一句**：**除了 `client.chat.completions.create()` 那一行会真的打网络，其他所有代码都只是在本地加工字符串、字典、列表。**
